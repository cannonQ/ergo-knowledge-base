# EIP-0023: Oracle Pool v2.0

- **Authors:** @scalahub, @greenhat, @kettlebell, @SethDusek
- **Status:** Proposed (PR #41 — not yet merged, but live in production)
- **Created:** 07-Sep-2021
- **License:** CC0
- **Reference implementation:** [ergoplatform/oracle-core](https://github.com/ergoplatform/oracle-core)
- **Contracts source:** [eip-0023/contracts/](https://github.com/ergoplatform/eips/tree/cae50b72/eip-0023/contracts/)

> **Note:** Despite being unmerged, EIP-23 is the **live production protocol** powering the ERG/USD oracle pool and other data feeds on mainnet. Oracle Core v2 implements this spec.

Update to oracle pool v1.0 ([EIP-16](https://github.com/ergoplatform/eips/blob/eip16/eip-0016.md)). See also the [Oracle Pools developer overview](../../ecosystem/oracle-pools/overview_oracle-pools.md) for implementation details and the [contract analyses](../../ecosystem/oracle-pools/contracts/) for annotated ErgoScript.

## Motivation — v1.0 Drawbacks

1. Rewards generate a lot of dust
2. Current rewards are too low
3. Two types of pool boxes make dApps and update mechanism complex
4. Oracle tokens are non-transferable — oracles locked permanently (same for ballot tokens)

## Key Changes from v1.0

| Feature | v1.0 | v2.0 |
|---|---|---|
| Pool addresses | Two (epoch-prep + live) | **Single pool address** |
| Reward mechanism | ERG payouts (dust) | **Token rewards** accumulated in oracle boxes |
| Oracle boxes in refresh | Data-inputs (read-only) | **Inputs** (spent and recreated with reward) |
| Token transferability | Locked to original owner | **Freely transferable** (oracle + ballot tokens) |
| Pool box complexity | Contains refresh logic | **Compact** — refresh logic in separate box |
| Epoch tracking | Implicit | **Explicit epoch counter** in R5 |
| Funding process | Separate funding required | **No separate funding** — pool emits reward tokens |

## Parameters

| Parameter | Symbol | Default | Meaning |
|---|---|---|---|
| Epoch period | `epochLength` | 30 | Blocks per epoch (~60 min) |
| Buffer | `buffer` | 4 | Max height error for new epoch start |
| Total oracles | — | 15 | Max oracles posting data points |
| Min data points | `minDataPoints` | 4 | Min fresh data points to refresh |
| Max deviation | `maxDeviationPercent` | 5 | Max % spread between first/last sorted data points |
| Total ballots | — | 15 | Voters for governance updates |
| Min votes | `minVotes` | 6 | Threshold for update approval |

## Tokens

| Token | Quantity | Purpose | Location |
|---|---|---|---|
| Pool-NFT | 1 | Identify pool box | Pool box |
| Refresh-NFT | 1 | Identify refresh box | Refresh box |
| Update-NFT | 1 | Identify update box | Update box |
| Oracle tokens | 15 | Identify oracle boxes | Oracle boxes |
| Ballot tokens | 15 | Identify ballot boxes | Ballot boxes |
| Reward tokens | 100M | Oracle incentives | Pool box → Oracle boxes |

## Box Types and Registers

| Box | Tokens | Key Registers | Purpose |
|---|---|---|---|
| **Pool** | Pool-NFT, Reward tokens | R4: Rate (Long), R5: Epoch counter (Int) | Publish rate for dApps |
| **Refresh** | Refresh-NFT | — | Guards refresh logic |
| **Oracle** (×15) | Oracle token, Reward tokens | R4: PubKey (GroupElement), R5: Epoch counter (Int), R6: Rate (Long) | Post data points |
| **Update** | Update-NFT | — | Guards governance updates |
| **Ballot** (×15) | Ballot token | R4: PubKey (GroupElement), R5: Update box height (Int), R6: New pool hash (Coll[Byte]) | Vote for updates |

## Contracts

Five ErgoScript contracts implement the protocol:

- [Pool Contract](../../ecosystem/oracle-pools/contracts/pool-contract.md) — Minimal guard: requires refresh-NFT or update-NFT in second input
- [Refresh Contract](../../ecosystem/oracle-pools/contracts/refresh-contract.md) — Epoch validation, data point sorting/averaging, deviation check, reward emission
- [Oracle Contract](../../ecosystem/oracle-pools/contracts/oracle-contract.md) — Owner-signed data posting, reward accumulation, token transfer
- [Ballot Contract](../../ecosystem/oracle-pools/contracts/ballot-contract.md) — Owner-signed voting, update participation
- [Update Contract](../../ecosystem/oracle-pools/contracts/update-contract.md) — Governance threshold check, pool box replacement

## Transactions

| Transaction | Inputs | Purpose |
|---|---|---|
| **Refresh pool** | Pool + Refresh + Oracles | Average data points → update pool rate |
| **Publish data point** | Oracle | Oracle posts current rate |
| **Extract reward tokens** | Oracle | Withdraw accumulated rewards |
| **Transfer oracle token** | Oracle | Change oracle ownership |
| **Vote for update** | Ballot | Cast governance vote |
| **Update pool** | Pool + Update + Ballots | Replace pool box script |
| **Transfer ballot token** | Ballot | Change ballot ownership |

### Refresh Transaction Detail

The refresh is the core transaction:
1. Pool box (input 0) requires refresh box as input 1
2. Refresh contract validates: epoch elapsed, min data points posted, sorted in increasing order, max deviation check
3. Each oracle box is **spent** (not data-input) and recreated with +1 reward token
4. Pool box output: averaged rate in R4, incremented epoch counter in R5
5. Collector (tx creator) receives n+1 reward tokens; other oracles get 1 each (incentivizes including all valid oracles)

### Update Rules

Parameters are hard-wired in the refresh contract. Updating one component may require updating others:

| To Update | Must Also Update |
|---|---|
| Pool params (epochLength, etc.) | Refresh-NFT + Refresh box |
| Oracle tokens | Refresh-NFT + Refresh box + Oracle boxes |
| Update-NFT | Update box + Ballot tokens + Ballot boxes |
| Reward tokens | Pool box |
| Ballot tokens | Update-NFT + Update box + Ballot boxes |

Old boxes left for garbage collection via storage rent; their tokens become available to miners.
